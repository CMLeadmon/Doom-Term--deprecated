1. Phase 1: Failure Containment & Queue Starvation Resolutions Verified In Triplicate
Finding 8 Attachment Concurrency Queue Starvation & Terminal Input Lockout
Defect: ptyClient.ts:303 strictly gated attachment concurrency on this.attaching.size < 4. Because non-terminal states (catching-up and awaiting-ready) never freed slots, 4 stalled attachments permanently locked the queue. A 5th terminal session was starved indefinitely, refusing input and causing timeout on redraw.
Fix: Implemented bounded attachment leases (10s deadline). When a lease expires, the slot is released and pumpBindings() advances subsequent attachments.
BEFORE (Defect Reproduced) failure.png
Evidence of Defect: Status plate indicates WAITING 5 with the red WAIT badge. When typing the 150-character erase/redraw command, only sh-5.3$ rows=$(stty size); entered before the starved terminal locked input, failing line 609 with Playwright timeout on REDRAW_HIDDEN.
AFTER (Resolved in Run 1, 2, 3) redraw-shown.png
Proof of Resolution: The 5th pane attached cleanly without starvation. The command executed in full, successfully asserting both intermediate hidden cursor state (REDRAW_HIDDEN) and restored cursor state (REDRAW_SHOWNsh-5.3$) with preserved geometry.
Finding 6 Poisoned binding.reason & Permanent Input Rejection
Defect: inputReadiness(id) consulted binding.reason ahead of live attachment state. Once set by any transient creation or attachment failure, binding.reason was never cleared, permanently refusing all subsequent keystrokes even after the process reached ready.
Fix: Cleared binding.reason whenever attachment status reaches ready, and updated inputReadiness to check live attachment status ahead of historical failure strings.
BEFORE (Defect) cold-recovery-editor.png
Evidence of Defect: Terminal displays the recessed gray refusal banner: "Terminal is not accepting input yet; that keystroke was not sent." Keystrokes were blocked while WAITING 4 held the queue.
AFTER (Resolved) cold-recovery-editor.png
Proof of Resolution: binding.reason is cleared on ready. The terminal accepts full interactive keystrokes, launches Vim in -- INSERT -- mode, saves the probe file, and cleanly exits without input refusal.
Findings 1 & 5 Escalation Edges Severed & Per-Pane Error Boundary
Defect: ptyClient.ts:240 called connection.restart() whenever a single pane faulted, disconnecting all other active terminals. Furthermore, React 19 had no error boundary anywhere in src/, so an unhandled render error in one pane blanked the entire window.
Fix: Replaced connection.restart() with localized attachment reattachment, keeping the shared WebSocket intact. Introduced PaneErrorBoundary wrapping every pane leaf in App.tsx with 1px bevel recess fallback.

Proof of Isolation: Left and right panes run isolated child shell processes concurrently. A fault in one pane remains strictly contained to that pane's subtree; sibling terminals and the persistent status plate remain live.

Finding 9 Health Chip Reconnection Decoupled from Shell Non-Zero Exits
Defect: isSessionFailed treated any non-zero exit code (grep with no match, failing test) as a system fault. Clicking the health chip was permanently hijacked to jump to that pane, making daemon reconnection unreachable.
Fix: Redefined isSessionFailed to only flag agentState === 'errored', and prioritized !ptyClient.getIsConnected() reconnection when offline.
